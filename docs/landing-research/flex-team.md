# flex.team landing reference

Source: https://flex.team/

Note: Cursor Cloud instructions prohibit Computer Use and interactive screenshot loops. This analysis uses read-only page extraction and translates the observed section/content structure into landing decisions.

## Section sequence and intent

1. Hero: names a new category, "Relations Driven AX," then explains the product as AI that understands the organization.
2. Problem framing: challenges the status quo that simply buying AI seats creates transformation.
3. Category education: separates individual AI usage from organization-wide AI transformation.
4. Three-part proof: "knows the user," "knows before people ask," "knows all data context."
5. CTA: invites enterprise evaluation after the product worldview is established.

## Content strategy

- The page succeeds by making a clear enemy: token spend and individual AI usage are not real AX.
- Each feature is framed as a different type of context awareness.
- The product is positioned as an organizational brain, not a tool in one workflow.

## Design style

- Enterprise SaaS tone: concise, authoritative, category-defining.
- Numbered sections are meaningful because they explain a doctrine in order.
- The copy uses repeated phrasing to make the thesis memorable: "바로 알고, 이미 알고, 모두 아는 AI."

## What SSOTA should adapt

- Create a category contrast: "more coding agents" is not the same as "an aligned agent team."
- Use a three-part doctrine for SSOTA:
  1. agents know the product intent,
  2. agents know what evidence to read before work,
  3. agents write decisions back for the next agent.
- Make the right-side preview feel like an operating system for product intent, not a static document.

## What SSOTA should avoid

- Do not make the message too abstract. SSOTA needs a visible software-development workflow and MCP surface.
- Avoid borrowing HR/organization metaphors too directly; the product should stay grounded in agentic software delivery.
