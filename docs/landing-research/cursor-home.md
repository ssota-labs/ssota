# Cursor homepage landing reference

Source: https://cursor.com/

Note: Cursor Cloud instructions prohibit Computer Use and interactive screenshot loops. This analysis uses read-only page extraction and translates the observed section/content structure into landing decisions.

## Section sequence and intent

1. Hero: "Cursor is your coding agent for building ambitious software" with immediate download/demo CTAs.
2. Trust band: world-class team adoption.
3. Agent proof: agents turn ideas into code, run autonomously, work in parallel, and produce reviewable walkthroughs.
4. Surface expansion: terminal, Slack, GitHub, and editor workflows.
5. Product depth: autocomplete, model selection, codebase understanding, enterprise durability.
6. Momentum: changelog, research highlights, final CTA.

## Content strategy

- The page shows a product-like mock in the hero so the abstract agent promise feels real.
- It sells delegation: users focus on decisions while agents execute.
- It repeats proof that agents build, test, and demo work end to end.

## Design style

- High-contrast, polished developer tool aesthetic.
- Large thesis copy with a dense app mock that demonstrates real agent status, task history, models, and completion summary.
- Credibility comes from recognizable logos/testimonials and product velocity.

## What SSOTA should adapt

- Use a hero app preview with agent work items, status, evidence, and review state.
- Emphasize the gap above Cursor: Cursor can run agents; SSOTA keeps multiple agents aligned to product intent.
- Use language like "focus on product decisions while agents execute against approved context."

## What SSOTA should avoid

- Do not compete as another coding agent/editor.
- Avoid too many model/provider claims. SSOTA should stay model- and agent-agnostic.
- Do not make the mock look like a code editor; it should look like a CPO/control-plane workspace.
