Company Workspace Surface Boundaries

stage
draft
specType
system-model
summary
관계형 도메인 정본, 고객 경험, 전문가 운영, 선언적 조회 화면의 책임 경계를 정의한다.

Contract

비즈니스 정본과 불변식은 도메인 모듈이 소유한다. 고객·전문가 UI는 도메인 API가 제공한 typed view model을 사용한다. 그래프와 선언적 페이지 spec은 검색·조회·구성의 projection이며 정본 쓰기 경로가 아니다.

Components

  • Domain modules — Finance, Legal, HR, Equity, Operations의 관계형 정본과 명령
  • Customer Workspace — 상태, 요청, engagement, 보고서와 문서
  • Expert Workspace — portfolio, review queue, evidence와 승인
  • Read projections — company snapshot, risk register, search/context index
  • Shared UI primitives — table, detail, timeline, evidence, review, diff, approval

Interfaces

  • 핵심 쓰기는 createNode가 아니라 도메인 명령으로 제공한다.
  • 고객 UI는 자신의 company scope와 승인된 결과만 조회한다.
  • 전문가 UI는 할당된 고객과 engagement의 검토·승인 인터페이스를 사용한다.
  • 공통 셸은 identity, company context, search, notification만 소유한다.

Boundaries

  • 고객과 전문가 surface는 route와 layout 수준에서 분리한다.
  • 도메인별 transactional workbench는 명시적 코드로 작성한다.
  • json-render는 read-only dashboard, report, 고객별 가벼운 구성에 한정한다.
  • JSONB는 외부 원본과 롱테일 payload에 사용하고 핵심 검색·제약 필드는 컬럼으로 승격한다.
  • context graph는 도메인 정본에서 재생성 가능해야 한다.

Acceptance

  • 동일 비즈니스 레코드가 graph와 domain table의 이중 정본이 되지 않는다.
  • 고객·전문가 화면의 권한 상승이 클라이언트 상태만으로 발생하지 않는다.
  • 도메인 workbench가 자유 JSON action 정의에 의존하지 않는다.
  • 신규 도메인 모듈을 추가해도 공통 셸과 persona 경계가 유지된다.
