Persona Workspaces with Explicit Workflow Pages

stage
accepted
summary
고객과 전문가 workspace를 분리하고 핵심 업무는 명시적 typed page로, 선언적 UI는 조회·보고 구성에 한정한다.

Context

generic CRUD와 graph editor는 시스템 구조를 잘 보여주지만 고객의 다음 행동이나 전문가의 검토 판단을 안내하지 못한다. 고객과 전문가는 같은 회사 데이터를 보더라도 목적, 밀도, 권한, 오류 처리 방식이 다르다.

Decision

Customer Workspace와 Expert Workspace를 route와 layout 수준에서 분리한다. 핵심 transactional flow와 domain workbench는 typed React page와 명시적 server action/API로 구현한다. json-render는 dashboard, report, read-only projection과 가벼운 고객별 구성에 사용한다.

Consequences

  • persona별 정보 구조와 접근 제어를 이해하기 쉬워진다.
  • 공통 UI는 primitive와 page grammar 수준에서 공유하고 거대한 조건부 page component는 만들지 않는다.
  • 새 도메인은 Overview, Records, Workbench, Detail 문법을 따르되 모든 화면을 만들 필요는 없다.
  • 기존 GRAPH-08의 “모든 페이지 json-render” 규칙은 구현 PR 전에 supersede해야 한다.

Alternatives considered

  • 하나의 Console에서 권한별 숨김 — 조건 조합과 정보 밀도 충돌이 커진다.
  • DB schema별 CRUD 페이지 — 구현은 단순하지만 사용자 목표가 아니라 저장 구조를 내비게이션으로 만든다.
  • 모든 화면을 JSON spec으로 생성 — 조회 구성에는 유리하지만 복잡한 상호작용과 타입 안전성을 약화한다.
