Relational Domain Cores with Graph Projections

stage
accepted
summary
핵심 비즈니스 데이터와 불변식은 도메인별 관계형 모델이 소유하고 그래프는 재생성 가능한 projection으로 사용한다.

Context

범용 node/edge + JSONB 모델은 새로운 타입을 빠르게 추가할 수 있지만 실제 회사 업무의 관계는 대부분 Finance, Legal, HR, Equity 등 한 bounded context 안에서 반복된다. 핵심 제약, 조인, 정합성 검사를 동적 schema와 edge에 맡기면 도메인 로직이 분산되고 이중 정본이 생긴다.

Decision

도메인별 관계형 schema와 명시적 command/query를 canonical source of record로 삼는다. JSONB는 외부 원본과 롱테일 payload에 사용한다. 검색, AI context와 드문 cross-domain 탐색을 위한 graph는 관계형 정본에서 파생하며 언제든 재생성할 수 있어야 한다.

Consequences

  • DB 제약과 transaction으로 핵심 비즈니스 불변식을 보장할 수 있다.
  • 도메인 모듈마다 migration과 API 계약이 필요해 초기 타입 추가 비용은 높아진다.
  • cross-domain 연결은 engagement, evidence, company 등 명시적 bridge에 한정된다.
  • 기존 graph 데이터의 cutover는 별도 migration release로 다룬다.

Alternatives considered

  • 모든 데이터를 generic node/edge로 유지 — 유연하지만 도메인 제약과 운영 UX가 약하다.
  • 도메인마다 별도 database — 강한 격리는 가능하지만 초기 팀 규모에서 운영·transaction 비용이 과하다.
  • 관계형과 graph를 모두 쓰기 정본으로 유지 — 동기화 실패와 충돌 해결 비용 때문에 채택하지 않는다.
