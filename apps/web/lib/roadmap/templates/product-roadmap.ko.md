## 16. 후속 문서 생성 계획

| Roadmap | 방향 정렬 후 | 프로덕트 로드맵의 목표를 일정으로 전환 |
| --- | --- | --- |
| ResearchInsight | 조사 진행 시 | 프로덕트 로드맵의 문제 정의를 뒷받침 |
| PRD | 요구사항 정의 단계 | 프로덕트 로드맵의 범위를 제작 요구사항으로 구체화 |
| 후속 문서 | 생성 시점 | 프로덕트 로드맵와의 관계 |
| InformationArchitecture | 설계 단계 | 프로덕트 로드맵의 사용자·콘텐츠 방향을 구조화 |
| Page / PageWireframe | 설계 단계 | 각 화면을 구체화 |
| ImplementationPlan | 제작 전 | 실행 작업으로 전환 |
| TestPlan | 제작 전후 | 완료 기준을 검수 항목으로 전환 |
| LaunchPlan / Runbook | 오픈 전 | 런칭 절차로 전환 |
| Retrospective | 오픈 후 | 결과와 학습을 다음 프로덕트 로드맵에 반영 |

## 17. 프로덕트 로드맵 완료 체크리스트

- [ ] 프로젝트 한 줄 정의가 작성되어 있다.
- [ ] 배경과 문제 정의가 근거와 함께 정리되어 있다.
- [ ] 목표, 성공 기준, 측정 방법이 정리되어 있다.
- [ ] 포함 범위와 제외 범위가 명확하다.
- [ ] 핵심 산출물과 완료 기준이 정리되어 있다.
- [ ] 고객 여정과 내부 처리 흐름이 연결되어 있다.
- [ ] 운영·제작·데이터 고려사항이 빠지지 않았다.
- [ ] 일정, 역할, 승인 구조가 정리되어 있다.
- [ ] 리스크와 전제 조건이 기록되어 있다.
- [ ] 후속 문서 생성 계획이 정리되어 있다.
